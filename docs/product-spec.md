# DaylyTrack：待辦事項工具首版產品規格

**狀態：** 已確認  
**確認日期：** 2026-10-29  
**目標平台：** Sites 託管的響應式網頁

## 1. 產品目標

讓單一使用者快速看清「哪些事項仍在處理」及「每件事項涉及哪些人」。記錄流程應簡短；主畫面重視卡片的可讀性，而非展示大量欄位或功能。

首版以桌面瀏覽器的版面為先，同時支援手機使用。卡片的完成、封存和刪除以水平滑動操作；桌面以滑鼠拖拉模擬相同手勢。

## 2. 資料模型

### 2.1 關係網

- 使用者可用自由文字命名關係網，例如「公司」、「社交」、「家庭」；不設固定類別。
- 一個關係網可有多位人物及多張事項卡片。
- 每張事項卡片只屬於一個關係網。
- 多於一個關係網時，使用者須指定一個「最優先呈現」的關係網；日後可在管理畫面更改。

### 2.2 人物

- 人物的必填資料只有名稱；不要求頭像、聯絡方式或職稱。
- 同一筆人物資料可加入多個關係網，也可出現在多張事項卡片上。修改名稱會更新所有引用該人物的卡片。
- 人物必須始終屬於至少一個關係網。可以有同名人物；同一關係網內出現同名人物時，介面提示使用者採用可辨識的名稱。
- 事項卡片選人時，只列出所屬關係網目前的成員。已從該網移出的人物仍可保留在既有卡片上；編輯這些卡片時保留原選擇，只有主動更換人物才需從目前成員中重選。

### 2.3 事項卡片

- 一張卡片代表一件一次性事項。建立時只需輸入事項名稱。
- 可選填目標完成日期與小時，使用 24 小時制，精確至整點；不設分鐘。所有時間均以香港時間理解。
- 可選填 `From` 與 `To`，各自最多一位人物，兩者可以都留空或只填一方。同一人物不可同時佔據兩欄。
- `From` 與 `To` 都有填寫時，自動顯示 `From → To`；只填一方時不顯示箭頭。空白人物欄仍保留在卡片版面中。
- 不設補充說明欄位。
- 資料上有「進行中／已完成」狀態，以及「待辦區／封存區」位置；逾期是由目標時間和狀態推算的呈現結果。

## 3. 主畫面與導覽

- 主畫面一次只顯示一個關係網。頁面頂部顯示關係網名稱；卡片上不重複標示。
- 每次重新開啟網站時，顯示「最優先呈現」的關係網。在同一次使用期間，切換到其他關係網後保持該選擇。
- 四格按鈕打開次級關係網選擇畫面。畫面列出各關係網名稱和「進行中」卡片數；提前完成但尚在待辦區的卡片不計入數字。
- 所選關係網的主畫面包含待辦區及封存區。封存區預設收在抽屜內，點擊指定按鈕才展開；切換關係網時，抽屜內容也隨之切換。
- 主畫面可快速新增事項：輸入名稱即可建立，目標時間與人物可同時選填或稍後補上。新增時預設歸屬目前的關係網。
- 卡片上常駐精簡的「編輯」按鈕。編輯或建立事項時，可經快捷入口新增人物，完成後返回原事項繼續操作。

### 3.1 待辦區排序

1. 逾期而仍在進行中的卡片優先顯示。
2. 其餘進行中卡片按目標時間由近至遠排列。
3. 沒有目標時間的進行中卡片排在其後。
4. 提前完成但尚未封存的卡片排在最後，以較淡的樣式呈現。

## 4. 卡片呈現

- 主畫面採單欄、由上而下的卡片列表；卡片本身橫向安排事項名稱、目標時間、狀態、`From`、`To`。
- 視覺以簡潔排版和線條為主。附件草圖只用作資訊結構與四格入口的參考，不是最終 UI。
- 狀態只以圓點顏色在畫面上表示，不加可見的狀態文字：
  - **紅色：** 進行中，且已到或超過目標時間。
  - **橙色：** 進行中，且尚未逾期；未設定目標時間亦屬此類。
  - **綠色：** 已完成，不受目標時間影響。

## 5. 完成與封存規則

| 情況 | 結果 |
| --- | --- |
| 進行中的卡片尚未到目標時間 | 留在待辦區；到達目標時間但仍未完成時，繼續留在待辦區並顯示紅點。 |
| 在目標時間前標記已完成 | 留在待辦區並顯示綠點；到達目標時間時自動移入封存區，也可提前手動封存。 |
| 在目標時間已過後標記已完成 | 立即移入封存區，並提示使用者；提供短暫復原機會。 |
| 沒有目標時間的卡片標記已完成 | 立即移入封存區。 |
| 封存卡片的目標時間被修改 | 維持封存；即使目標時間改到未來，也必須由使用者向右滑取回。 |

在待辦區修改已完成卡片的目標時間時，按新時間重新判定是否應自動封存。封存區中的卡片則遵守上表的手動取回規則。

## 6. 卡片操作

手機使用觸控滑動；桌面使用滑鼠按住卡片並水平拖拉。滑動只用於完成、封存、取回和刪除；編輯使用常駐按鈕。

| 卡片位置與狀態 | 操作 | 結果 |
| --- | --- | --- |
| 待辦區、進行中 | 向右滑 | 標記已完成；按第 5 節決定留在待辦區或立即封存。 |
| 待辦區、已完成 | 向右滑一次 | 拉出「改回進行中」與「封存」選項；可點擊任一選項。 |
| 待辦區、已完成，右側選項已拉出 | 再次向右滑 | 快速封存。 |
| 封存區 | 向右滑 | 返回待辦區，同時改為進行中。 |
| 任何卡片 | 向左滑一次 | 拉出「刪除」選項。 |
| 任何卡片，刪除選項已拉出 | 點擊「刪除」或再次向左滑 | 從畫面移除，短暫顯示「復原」。復原時恢復原有內容、狀態及位置。 |

拉出選項後，可向相反方向滑回原位，或點擊卡片以外的位置收起。封存區卡片的向右滑用於取回，不顯示待辦區已完成卡片的選項。

## 7. 管理畫面與刪除約束

- 主畫面負責新增、編輯與操作事項；管理畫面負責建立及管理關係網、人物與預設關係網。
- 卡片可改屬另一關係網。若原有 `From`／`To` 未加入新關係網，移動時要求先重新選人或清空相應欄位。
- 從關係網移出仍被該網卡片使用的人物前，提示受影響的卡片數；確認後允許移出，既有卡片仍顯示該人物。
- 若移出操作會令人物失去最後一個所屬關係網，先阻止操作；使用者須先把人物加入另一網，或明確永久刪除此人物。
- 永久刪除人物前，提示受影響的卡片數。確認後，清空所有相關卡片的 `From`／`To` 欄；若不再有兩位人物，箭頭亦隨之移除。
- 關係網仍有待辦或封存卡片時，不可刪除。若刪除關係網會令任何人物失去最後一個所屬關係網，也須先處理該人物。成功刪除關係網只解除其人物關聯，不連帶刪除仍屬其他關係網的人物。

## 8. 首版部署與範圍

- 首版在 Sites 試行，使用其託管、D1 持久資料儲存及 ChatGPT 身份限制，讓桌面與手機存取同一批資料。
- 不要求預先購買自訂網域或自行設立外部資料庫。部署時核對所用帳戶的實際存取範圍；Sites 官方文件指出，新站預設供站主及工作空間管理員存取。
- 首版不做電郵或手機推送提醒；只在網頁內顯示狀態、逾期與操作提示。
- 最終視覺樣式、顏色數值、動畫細節及技術實作可在設計與開發階段決定，但不得改變本文列出的資料和互動規則。

## 9. 首版驗收重點

1. 只輸入名稱即可在目前關係網新增卡片；空白 `From`／`To` 欄仍可見。
2. 同一人物可加入多個關係網並供多張卡片選用；卡片不可選取不屬於該網的新人物。
3. 在桌面拖拉與手機滑動均可完成第 6 節的操作，按鈕亦可觸發已拉出的選項。
4. 提前完成、逾期完成、沒有目標時間，以及手動封存，均符合第 5 節的位置規則。
5. 封存卡片修改目標時間後保持封存，向右滑才返回待辦區並改為進行中。
6. 人物及關係網的移除／刪除遵守第 7 節的提示和關聯約束。
7. 切換關係網後，待辦、封存與進行中數字只反映所選關係網；重新開啟網站回到預設關係網。
